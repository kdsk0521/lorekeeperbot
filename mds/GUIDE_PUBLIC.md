# Lorekeeper — AI TRPG 내러티브 봇

> **"세계를 건네주면, 이야기를 돌려줍니다."**

Lorekeeper는 Discord에서 작동하는 AI 기반 TRPG 서사 엔진입니다.
GM(게임마스터) 없이도 풍부한 서사, 살아있는 NPC, 장르에 맞는 분위기를 자동으로 만들어냅니다.

## 이런 봇입니다

### 일반적인 AI 챗봇과 다른 점

| | 일반 AI RP 봇 | Lorekeeper |
|---|---|---|
| **서사 품질** | 단순 대화 주고받기 | 카메라 워크, 감각 묘사, 시간 밀도를 갖춘 문학적 서사 |
| **NPC** | 일관성 없는 반응 | 심리 모델, 보이스카드, 자율 행동 시스템 |
| **세계관** | 맥락 금방 잊음 | 로어북 기반 세계 규칙, 발효(기억 압축), 연속성 추적 |
| **장르** | 고정 스타일 | 3계층 장르 감지 → 자동 톤/메카닉 적응 |
| **GM 기능** | 없음 | 판정, 둠(긴장), 기력/평정, 이벤트 스케줄링 |

### 지원 장르

로어북을 넣으면 자동으로 장르를 감지하고, 그에 맞는 메카닉과 분위기를 적용합니다.

- 판타지 / 다크 판타지
- 호러 / 심리 호러
- 느와르 / 하드보일드
- SF / 사이버펑크
- 로맨스 / 슬라이스 오브 라이프
- 액션 / 모험
- 코미디
- 그 외 혼합 장르

## 시작하기

### 1단계: 세계관 준비

```
!로어
```
로어북(세계관 설정 문서)을 업로드합니다. 텍스트를 직접 입력하거나 파일을 첨부할 수 있습니다.

- **파일 첨부** → 기존 로어를 덮어씁니다
- **텍스트 입력** → 기존 로어에 추가됩니다

로어북에서 NPC, 장르, 세계 규칙이 자동으로 추출됩니다.

### 2단계: NPC 등록 (선택)

```
!npc 이름
(프로필 텍스트)
```
NPC를 수동으로 등록할 수 있습니다. 로어북에서 자동 추출된 NPC도 있지만, 상세 프로필은 수동 등록이 더 정확합니다.

### 3단계: 캐릭터 설정

```
!가면 캐릭터이름
(캐릭터 설명)
```
플레이할 캐릭터를 등록합니다. 여러 캐릭터를 등록하고 전환할 수 있습니다.

### 4단계: 준비 확인 & 시작

```
!준비        ← 세션 준비 상태 점검
!시작 [상황]  ← 세션 시작 (선택적으로 첫 상황 제시)
```

이후에는 자유롭게 행동을 입력하면 됩니다. Lorekeeper가 서사로 응답합니다.

## 핵심 시스템

### NPC 시스템

Lorekeeper의 NPC는 단순한 대화 상대가 아닙니다.

**심리 모델**: 매 턴 Flash AI가 NPC의 심리 상태를 분석합니다 — 방어기제, 감정, 자기인식 수준, 거짓말 여부까지.

**보이스카드**: NPC별 정적 성격 지침. 말투, 가치관, 대인관계 스타일을 일관되게 유지합니다.

**자율 행동**: NPC가 스스로 행동을 개시할 수 있습니다. 9가지 심리적 트리거 (애착, 반발, 정보 갈망, 비밀, 도덕적 판단 등)에 기반합니다.

**관계 추적**: 5단계 깊이 — 면식 → 지인 → 친분 → 신뢰 → 유대. 서사 내 상호작용에 따라 자연스럽게 변화합니다.

**장면별 프로필 로딩**: NPC 프로필이 크더라도 현재 장면 유형(전투/사교/친밀/탐색 등)에 필요한 섹션만 선택적으로 로딩합니다.

### 장르 감지 (3계층)

로어북을 업로드하면 AI가 3개 레이어로 장르를 분석합니다:

- **A. Stage** (무대) — 세계관 설정 (판타지, 현대, SF 등)
- **B. Flavor** (향) — 스타일/기법 (고딕, 사이버펑크, 하드보일드 등)
- **C. Lens** (렌즈) — 서사 톤 (호러, 로맨스, 코미디 등)

C계층에서 **메카닉 프로필**이 자동 생성됩니다 — 어떤 자원이 주요한지(기력 vs 평정), 둠 단계 이름, 이벤트 성격 등이 장르에 맞게 결정됩니다.

### 기억 시스템

| 계층 | 역할 | 용량 |
|------|------|------|
| **세션 히스토리** | 최근 대화 원문 | ~20 메시지 |
| **발효** | 25턴 단위 압축 요약 | ~25턴마다 |
| **DEEP 압축** | 8회 발효 후 초압축 | ~200턴마다 |

세션이 길어져도 핵심 기억은 유지됩니다. 발효(Fermentation)는 와인 숙성처럼 — 시간이 지날수록 중요한 것만 남습니다.

### 연속성 추적

Lorekeeper는 장면의 연속성을 2계층으로 추적합니다:

- **DAI 스냅샷**: 장소, 에너지, 장면 유형, 열린 서사 실타래 (코드 레벨, API 비용 0)
- **렌더 지문**: 시선, 조명, 팔레트, 리듬, 미해결 감각 (AI 추출)

이전 프레임 정보가 다음 턴에 전달되어, "갑자기 낮이 되는" 같은 연속성 파괴를 방지합니다.

### PC 자율성 보호

Lorekeeper는 **절대로 PC의 대사나 내면을 대신 쓰지 않습니다**.

- NPC가 PC에게 행동을 시도할 수 있지만 (밀치기, 잡기 등)
- PC가 뭐라고 말했는지, 뭘 생각하는지는 플레이어만 결정합니다
- 3중 감지 시스템 (프롬프트 지시 + 텔레스코프 자기점검 + 코드 레벨 매칭)으로 사칭을 차단합니다

## DLC 모듈

DLC는 ON/OFF 가능한 선택적 시스템입니다. 모듈을 꺼도 기본 서사는 정상 작동합니다.

```
!모듈              ← 전체 상태 확인
!판정              ← 판정 모듈 토글
!둠모듈            ← 둠 모듈 토글
!이변              ← 이변(스토리텔러) 모듈 토글
!기력모듈          ← 기력/평정 모듈 토글
```

### 판정 시스템 (⚖️)

행동의 성패를 1d100으로 결정합니다.

- **포지션 기반**: 상황에 따라 유리(Dominant)/중립(Neutral)/불리(Desperate)
- **크리티컬**: 96-100 대성공, 1-5 대실패
- **서사 분기**: 판정 결과가 서사의 방향을 바꿉니다

### 둠 (⏰ 긴장 시계)

세션 전체의 긴장도를 0-100으로 추적합니다.

```
평온(0-15) → 불안(16-35) → 고조(36-55) → 위기(56-75) → 임계(76-94) → 클라이맥스(95-100)
```

장르에 따라 이름과 분위기가 달라집니다. 판정 실패, 시간 경과, 이벤트가 둠을 올립니다.

**상황 시계**: 특정 위협에 대한 하위 시계(4/6/8칸). "추적자 접근 ████░░" 같은 구체적 압박.

### 기력/평정 (💪)

캐릭터의 신체+정신 상태를 2축으로 추적합니다.

| 축 | 의미 | 감소 원인 | 회복 |
|---|---|---|---|
| **기력** | 체력 + 의지 | 전투, 부상, 과로 | 휴식, 식사 |
| **평정** | 정신 + 사회성 | 공포, 배신, 고립 | 대화, 안전한 장소 |

단계: 충만(80+) → 안정(60-79) → 동요(40-59) → 고갈(20-39) → 붕괴(0-19)

장르에 따라 주요 자원이 달라집니다 — 호러/액션은 기력, 로맨스/코미디는 평정이 핵심.

### 스토리텔러 (🌪️ 이벤트)

세계에서 자연스럽게 사건이 발생합니다.

- 타이밍: 서사 에너지와 경과 턴에 따라 자동 스케줄링
- 다양성: 최근 5개 이벤트 태그 추적, 반복 방지
- 둠 연동: 높은 긴장도에서는 더 극적인 이벤트
- 로어 연동: 로어북에 등록된 이벤트가 우선

## 기술 아키텍처

> 이 섹션은 Lorekeeper의 내부 구조에 관심 있는 분들을 위한 것입니다.

### 듀얼 브레인

Lorekeeper는 두 개의 AI를 사용합니다:

```
┌─ THEORIA (좌뇌 / Flash) ────────────────┐
│ 역할: 분석, 데이터 추출, 심리 모델링      │
│ 출력: DAI (구조화된 JSON)                 │
│ 비용: 저렴                               │
└──────────────┬───────────────────────────┘
               │ JSON
┌──────────────▼───────────────────────────┐
│ RENDERER (우뇌 / Pro)                     │
│ 역할: 문학적 서사 렌더링                   │
│ 입력: 34슬롯 프롬프트 + DAI               │
│ 출력: 서사 텍스트 + 숨겨진 추론            │
└──────────────────────────────────────────┘
```

**Theoria**(좌뇌)가 장면을 분석하고 — NPC 심리, 장면 에너지, 서사 방향, 연속성 체크 —
**Renderer**(우뇌)가 그 분석을 토대로 서사를 씁니다.

코드 파이프라인이 중간에서 UNE 모듈들(판정, 둠, 기력, 이벤트)을 처리합니다.

### 34슬롯 프롬프트 시스템

렌더러에게 보내는 지시는 34개의 번호가 매겨진 슬롯으로 구성됩니다:

```
[1-4]  핵심 지시 (AI 정체성, 서사 규칙, 렌더링 원칙)     ← 최우선
[5-9]  세계 데이터 (세계관, PC, NPC, 로어, 기억)
[10-12] 맥락 (시간, 챕터, 사회)
[13-17] 인지 (Theoria 분석, 심리, 장면, 대사 지시)
[18-25] 규칙 (PC 자율성, 판정, 산문 규칙)                ← 정적 리센시
[26]   캐시 경계
[27-34] 동적 데이터 (히스토리, 이벤트, 출력 지시)          ← 최종 리센시
```

LLM의 Primacy/Recency 효과를 활용 — 가장 중요한 지시를 처음과 끝에 배치합니다.

### 3축 연출 표기

매 턴 Theoria가 연출 지시를 3개 축으로 생성합니다:

- **♪ 음악**: 감정 밀도 (dynamics pp~ff, tempo largo~presto)
- **▶ 카메라**: 공간 구성 (구도, 배치, 전환, 조명)
- **◎ 사진**: 시간 밀도 (벌브~프리즈, 광학 필터)

예시: `릴리스 | ♪ mp, andante, legato | ▶ 미디엄 클로즈업, 정면 [역광] | ◎ 실시간, 차가운 파랑`

### 텔레스코프 프로토콜

렌더러 내부에서 작동하는 10단계 자기점검 체인:

```
┣ [Immersion] [PCAutonomy] [CameraEye] [Iceberg] [Impersonation]
  [PhysicsCheck] [EmotionSource] [TheoryAlign] [GenreCoherence] [Continuity] ┫
```

사용자에게는 보이지 않지만, 서사 품질을 턴마다 검증합니다.

### 턴당 처리 흐름

```
유저 입력
  ↓
1. Theoria 분석 (Flash) → DAI JSON
  ↓
2. UNE 파이프라인 (코드)
   ├── Storyteller: 이벤트 스케줄링
   ├── Doom: 긴장도 업데이트
   ├── Vigor/Composure: 상태 처리
   └── Judgment: 판정 (필요 시)
  ↓
3. 34슬롯 프롬프트 조립
  ↓
4. Main 렌더링 (Pro) → 서사 텍스트
  ↓
5. 후처리 (Flash)
   ├── 신체 상태 추출
   └── 사회/서사/퀘스트/세계/지문 추출
  ↓
6. 상태 업데이트 → 다음 턴 준비
```

### 비용 구조
